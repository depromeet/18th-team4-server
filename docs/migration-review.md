# 문서 이관 심사 기준

Epic #117 · 1단계. 기존 문서를 4분류 구조로 옮길 때 적용하는 기준.
이 문서 자체는 이관이 끝나면 판정표를 docs/record/ 로 옮기고 삭제한다.

## 4분류 구조

| 위치 | 성격 | 갱신 시점 |
|---|---|---|
| `CLAUDE.md` | 목차 + 매 세션 적용 규칙 | 규칙이 생기거나 죽을 때 |
| `docs/conventions/` | 컨벤션 상세·예시 | 규칙이 바뀔 때 |
| `docs/domain/` | 기능 설계·도메인 지도 | 기능이 추가·변경될 때 |
| `docs/record/` | 의사결정·사고 기록 | 추가만 한다 (기존 기록은 수정하지 않는다) |
| `docs/ops/` | 운영 정책·인프라 | 인프라가 바뀔 때 |

## 심사 원칙

1. **기본값은 망각이 아니라 판정이다.** 기존 문서의 모든 규칙(문단·표의 행
   단위)은 아래 셋 중 하나로 명시적으로 판정하고 판정표에 남긴다.
   - **유지** — 그대로 새 위치로 이동
   - **수정** — 내용을 고쳐서 이동 (무엇을 왜 고쳤는지 한 줄)
   - **폐기** — 삭제 (왜 더는 유효하지 않은지 한 줄)
2. **CLAUDE.md 잔류 기준: "이 규칙을 모르면 AI 가 다음 PR 에서 실제로 위반을
   저지르는가?"** 예스면 잔류, 노면 `docs/conventions/` 등으로 이동하고
   CLAUDE.md 에는 링크만 남긴다. 배경 설명·긴 코드 예시·인프라 스펙은
   위반이 성립하지 않으므로 이동 대상이다.
3. **규칙인데 문서에 없는 것도 심사 대상이다.** 코드에는 적용됐지만 문서화
   안 된 패턴(예: `@AuthenticatedUserId` 인증 하네스)은 "추가" 판정으로
   판정표에 올린다.
4. 심사 중 발견한 규칙 간 불일치는 그 자리에서 해소한다 — 어느 쪽이 맞는지
   판정하고 진 쪽을 수정/폐기.
